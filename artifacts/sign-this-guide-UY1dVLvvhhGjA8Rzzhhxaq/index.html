Sign This Guide

Sign This

Setup & instructions · version 0.1.0

Sign This puts a digital signature on your files so Windows and macOS know who made them and that nobody changed them. You drop files in, press the seal, and it's done. It signs Windows programs and installers (.exe .dll .msi .msix .ps1), Mac apps (.app .dmg .pkg), and anything else with a separate signature file.

Try it first. The interactive demo is the real app with sample files and accounts. Nothing is really signed or saved.

The first time, it creates a Sign This folder in your home folder for its settings and a ready-to-use self-signed certificate. To add a desktop icon and a right-click Send to → Sign This entry, run SignThis install-shortcuts once.

3Sign files

  1. On the Sign tab, drag files onto Drop files here, click it to pick files, or paste a file or folder path and click Add.
  2. Each file is matched to a certificate automatically. Use the drop-down beside a file to pick a different one.
  3. Press the red Sign This seal. Green Signed ✓ means done; the log on the right shows every step.

Dragged or picked files are copied to Signed by Sign This in your home folder and signed there. Files added by path, Send to, or the desktop icon are signed in place. Practice run shows what would happen without changing anything.

4Connect your accounts

Go to Certificates → Add certificate. The top of the list connects accounts for you. Sign in or scan, pick what it finds, and the form fills itself in.

Or set one up by hand: certificate file (.pfx/.p12), self-signed, cloud or hardware key (AWS KMS, Google Cloud KMS, DigiCert KeyLocker, SSL.com eSigner, YubiKey), or Sigstore. Every form has Setup links at the top. If a card says a tool is missing, the tool name links to its download.

Passwords are kept in the computer's secure storage (Windows encryption, macOS Keychain, Linux keyring), never in a file. When editing, leave a password empty to keep the saved one.

Which certificate is used? The highest switched-on card that handles the file type. New certificates are added at the top, so your Azure account takes over from self-signed automatically. Use ↑ ↓ on the cards to change the order.

Before connecting Azure

  1. In the Azure portal, create a Trusted Signing account and finish identity validation (quickstart).
  2. Create a certificate profile and give yourself the Trusted Signing Certificate Profile Signer role.
  3. Install the Azure CLI, plus jsign (any computer, needs Java) or signtool with the Trusted Signing dlib (Windows).

Before connecting Apple

  1. Join the Apple Developer Program.
  2. Create a Developer ID Application certificate (and Developer ID Installer for .pkg), download it, and double-click it on your Mac.
  3. For notarization, create an App Store Connect API key and enter it in the form.
  4. No Mac? In the Apple form choose Certificate file and upload your Developer ID .p12 and the API key JSON.

5The self-signed certificate

It works right away with no account. Use it for internal tools and testing only, because customers' PCs will still show a warning. To make company PCs trust it, click Download .cer on its card, then on each PC run in PowerShell as administrator:

Import-Certificate -FilePath selfsigned.cer -CertStoreLocation Cert:\LocalMachine\Root
Import-Certificate -FilePath selfsigned.cer -CertStoreLocation Cert:\LocalMachine\TrustedPublisher

IT can push it to every PC with Intune or Group Policy instead.

6More

  • Appearance tab: background (fountain pen & paper, black, white, colors), 3D effects on/off, and General settings for the program name Windows shows, the signed-files folder and the log file.
  • Signing log: every signing is recorded in signing-log.jsonl with time, file, SHA-256 fingerprint, certificate, user and computer.
  • Watch folder: SignThis watch signs anything copied into to-sign and moves it to signed.
  • Command line: SignThis sign <files or folders>, SignThis verify <files>, SignThis check.

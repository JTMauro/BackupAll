**Goal:** Build a tool for a client who forgot the password on their own Office file: diagnose and remove editing protection, and recover/decrypt password-to-open Word/Excel/PowerPoint files, delivered as a Matrix-themed offline browser app ("Kracken") plus a Python engine.

**Requirements & decisions:**
- Handle both Excel lock types: sheet/workbook protection (trivially strippable, not encryption) and password-to-open (AES; no bypass, must guess).
- Build a self-contained toolkit covering both cases (`excel_unlock.py`, wordlist, README); client will test afterward.
- Add a control panel with buttons for each action, 3D with shadowing, "Matrix" theme (digital rain, glowing 3D buttons, live command generation).
- Deliver both a hosted version and a downloadable local HTML app; hide the Python script under a separate tab; pop up the password in a modal when found.
- Make it work for any Office file (Word, PowerPoint, Excel) — same ECMA-376 encryption engine; per-type editing-protection strip.
- Save the cleared/decrypted file as `filename-cleared` keeping the original extension (`.docx`→`.docx`), not forced to .xlsx.
- Support both Standard (Office 2007-2013 / LibreOffice, AES-ECB+SHA-1) and Agile (2013+, SHA-512) encryption; fast synchronous hashes for speed.
- App name: **Kracken**.
- User pushed back that it was "only brute force"; add smarter attacks and run multiple strategies at once, each with its own live status line (lanes: clues+rules, wordlist+rules, combinator, dates, keyboard, masks; later breach/reuse lookup and Markov).
- STOP button must actually kill the worker processes (fixed via worker.terminate()).
- Add a holographic cube struck by lightning from various directions while cracking is in progress.
- "Use every tool you can muster - it is now a competition"; also user wants to help the client solve it (added a Clue Finder guided-interview tab).
- Add IRM/RMS rights-managed detection (reads `\x06DataSpaces` transforms) so the tool says when cracking cannot help (prompted by user's "RSA decrypter" question; explained password-to-open uses no RSA).
- Speed: user wanted ~10,000 guesses/sec; Claude explained Office deliberately uses 50k-100k hash iterations per guess so that is a GPU-only number; delivered ~16x speedup via allocation-free hash spins (~66/sec/core Office 2007).
- Trying the same password on 100 file copies gives no speedup (deterministic); instead centralize so each unique candidate is tried on exactly one instance (de-duplicated master stream, proven 0 duplicates across 200k candidates), fed to CPU core pool + GPU.
- Two sliders: turn on WebGPU and "Prefer System GPU" (GPU SHA-1 shader validated bit-exact on CPU; GPU execution labelled experimental, CPU is the always-correct floor).
- hashcat integration: browsers cannot launch programs, so one-click "BUILD RUNNER" exports `kracken_hash.txt` plus run scripts (`.command`, `.sh`, `.bat`) with the correct `-m 9400` mode; exact command shown on hover.
